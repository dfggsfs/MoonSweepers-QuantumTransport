# 量子传送 0.7.0：联机与规模调度测试版

适用 Moon Sweepers 1.0.4 / Steam Build 26203101 / Windows x64 / Lustral 0.1.0。

**验证边界**：用户已实测通过 0.2.1 的打包机→加压舱→压石机、多机分配及拆除机器。后续采集来源、月石交付和本版联机、性能优化已完成编译与离线检查，尚未经过实际双人游戏验收。离线重试模型和算法基准不等于 Steam 联机或游戏帧率验证。实际游戏测试由用户进行。

## 功能及安装要求

- 玩家背包、存放容器、明确登记的车辆料斗和近远机器人已入账月尘→加工机；打包机→加压舱→压石机→原版收集站，无距离限制。
- 月石交付只增加原版站点库存及贡献/加工品溢价；**仍需原版发射、结算才获得收益**，不会直接加钱或自动发射。满站时保留来源。
- 原版加工时间、配方、供电、采集奖励保留。未完成的采集工作不提前生成资源。月砂先分配，再供应月尘；默认压石机月尘目标为“输入月砂 + 1 kg 预备量”。同级公平供料，预算受限时轮转续传。
- 新增散落胶囊接入：仅使用未手持、未飞行、未在传送带上的真实资源。实体与其原始背包不会当作两份资源。
- 新增车库储仓：已经通过原版卸货进入储仓的月尘直接供给加工机，不再依赖车库出口传送带。保持卸货记录中的玩家归属，由单人或联机主机处理。默认 collect_garage_dust = true。
- Ctrl+F7 打开/关闭游戏内面板，含运输总览、来源库存、分页机器状态、分配规则和联机/调度摘要。侧栏可“启用／关闭量子传送”，状态持久保存，和 Ctrl+F8 同步。0.7.0 修复关闭误退出游戏的问题，Esc/右上角仅关闭面板；标签、翻页和开关不触发底层确认框。单人暂停时生产进度可能不变。
- 面板约每秒刷新，最多读取256条来源，按类别交错采样并标明范围；机器每页7台，客户端仅显示本机来源。会话累计自本次启动开始，重启后清零；preview 内是离线示例图，不是实机截图。
- 0.7.0：统一按钮状态，选中页持续高亮，禁用越界分页；加入悬停/按压反馈、开合与切页过渡、提示和配置保存反馈。机器页支持 PgUp/PgDn。reduce_dashboard_motion = true 可跳过动画，状态反馈保留。新增交互仍需你实测，物流规则不变。

**完整联机功能需要主机及每位需要自动采集的客户端安装相同 0.7.0 与兼容加载器。** 主机统一做工厂分配、机器人转运及交付；客户端只交接自己的背包、存放容器和当前控制车辆。车辆保留原登记贡献者。

只在主机安装：共享工厂、主机采集与机器人可运行；未安装客户端的背包、驾驶车辆不会被主机直接扣减，其原版手工打包并放下的胶囊可接入。只在客户端安装、主机未启用本版：自动交接暂停。

主机开启 enabled、enable_coop、collect_loose_capsules，客户端开启 enabled、enable_coop；双方相应的采集开关均允许才建立新交接。关闭开关停止新增转运；已发出的真实胶囊仍是世界资源。消息携带最终来源快照与原版编号胶囊，主机接收后记录回执。初次发送返回失败会回滚来源；成功排队后只重发相同编号，不重新打包，不因超时直接退款。默认每客户端最多 8 个待消耗胶囊。

本版不承诺主机迁移或异版本兼容。原生方法异常、强制结束进程及未保存退出尚无实机验证，不能声称任意崩溃下绝不丢物或复制。异常记录后本会话停止物流。断线后先核对真实库存和胶囊，避免手动补发同一批资源。

关闭游戏后运行“安装.cmd”。先检查，备份旧插件、原配置及存档到本包 backups，再安装并复查；不会启动游戏或改写保存文件内容。保留原配置，下次加载器启动会补齐新项。其他电脑也需要对应游戏与 Lustral；ZIP 不含游戏、加载器、存档或备份。“运行前检查.cmd”仅检查文件与依赖，不代表玩法验收。

## 实测步骤

0. 新功能：关闭 collect_vehicle_dust，先用原版卸货把月尘存入车库，放置有供电的加工机，核对车库减少量与输入/加工增量。测试满仓、多个车库、多玩家归属、保存读档及拆除。Ctrl+F7 核对总览车库行、三页切换、翻页、不同分辨率和关闭/ESC/场景切换后的鼠标恢复。新功能尚待你实际验证。
1. 单人回归：原存档检查加工链、玩家/车辆/机器人采集和月石入站。站点增加对应来源减少，发射前钱包不因交付增加。满仓保留、腾出空间续传，保存退出重进核对。
2. 双人基础：同版主机与客户端各自采集、驾驶车辆，观察输入槽、加工中、成品、站点及胶囊。日志角色应分别为 Host、Client；客户端不执行工厂分配及站点记账。
3. 满仓积压：让接收端满仓或断电，客户端持续采集。需求满足后新增交接暂停，待处理胶囊不应无限增长；腾出空间应继续。拿起胶囊后须放下才会自动接入。
4. 借车与切换：交换驾驶、停放取回、切换存放容器及近远机器人，确认库存只扣一次并保留贡献者。未知控制状态的库存应留在原处。
5. 断线与读档：有交接胶囊时让客户端退出重连，核对来源、胶囊、机器及站点之和；由主机保存退出、重开邀请后继续采集，检查新资源没有被旧回执误删。等网络与加工稳定后比较数量。
6. 主机单装：未装客户端手持库存不自动扣减，原版打包放下可转运。客户端单装显示等待主机 Mod。
7. 规模：逐步增加来源、机器，保持 Info 日志；观察持续运行、批量拆建、保存及场景切换，Ctrl+F10 留快照。双方分别运行“收集日志.cmd”，记录主机身份、操作、时间与大致规模。

核对数量需计入配方消耗、加工中的材料、已发射货物和手持/飞行胶囊。测试成品槽路径时可先断开成品输出带，便于观察。

## 配置与性能

配置文件：C:\Program Files (x86)\Steam\steamapps\common\Moon Sweepers\Lustral\config\local.quantumtransport.toml。关闭游戏后修改，重启生效；完整默认值见 default-config.toml。

| 配置 | 默认值与作用 |
| --- | --- |
| enabled | true；Ctrl+F8 游戏内切换并保存 |
| dust_distribution | RecipeBalanced；CapacityFair 按整个输入槽容量接收月尘 |
| chamber_dust_priority / press_dust_priority | 0 / 0，-100至100；越大越先供应，持续高级需求可能延迟低级 |
| press_dust_buffer_kilograms | 1，按现有月砂需求额外预备月尘，0至12 |
| packager_dust_reserve_kilograms | 0，每打包机跨贡献者合计保留，仅约束量子路径 |
| collect_player_dust / collect_vehicle_dust / collect_robot_dust | true，分别控制采集来源 |
| collect_garage_dust | true，已卸入车库储仓的月尘独立接入 |
| enable_dashboard | true，Ctrl+F7 游戏内状态面板与运输总开关 |
| reduce_dashboard_motion | false；true 跳过开合、切页和按钮动态效果 |
| deliver_stone | true，成品月石交付站点 |
| enable_coop / collect_loose_capsules | true，联机与散落胶囊接入 |
| poll_interval_milliseconds | 100，范围16至1000；增大减少频率并增加延迟 |
| max_sources_per_tick | 128，每轮来源检查上限，16至4096 |
| max_receiver_samples_per_tick | 128，每轮输入口采样上限，16至4096；转入前再次核对 |
| max_transfers_per_tick | 128，每轮库存事务上限，16至4096 |
| tick_budget_milliseconds | 4，主机/单人热调度软预算，1至20 |
| catalog_refresh_milliseconds | 1000，兜底索引刷新，250至10000；结构/集合数量变化提前刷新 |
| network_sync_milliseconds | 250，提醒原版同步的最短间隔，100至2000；实际发送仍按原版去重节流 |
| max_client_capsules_in_flight | 8，客户端待消耗胶囊上限，1至32 |
| client_capsules_per_tick | 1，每轮客户端最多交接数，1至4 |

来源、输入口和实际提交分配不同阶段预算，中断后从已检查的位置续扫。**4 ms 是软预算**：索引重建、计划计算、保存、日志和单次原生调用不能任意中断，可能超过预算；客户端报告序列化也不在此承诺内。批量拆建仍可能有峰值，需要实机日志。规模变大后可能多轮才能供完，不承诺所有机器同一帧收货。

## 日志

目录：C:\Program Files (x86)\Steam\steamapps\common\Moon Sweepers\Lustral\data\local.quantumtransport\diagnostics。

- Ctrl+F9 切换 Info/Debug，Ctrl+F10 写 status.json。默认15秒汇总，JSONL约2MB轮转并保留两份旧日志，Debug明细每秒最多20条。run_native_checks 默认 false，不自动创建机器或测试世界。
- network：角色、待处理胶囊、待回执包、已创建/接收对象、重复包数、暂缓接收原因与初次发送失败数。重复包本身不表示重复入库。
- scheduler：索引来源、实际检查数、输入口采样、事务数、轮耗时、最近索引耗时、峰值、让出次数及消耗回执区间数。峰值不是完整游戏帧时间。
- stats.NonemptySources 保留旧字段名，本版是本轮来源窗口大小；AvailableKilograms 是实际扫描部分库存和，不是全图总量。类别计数为索引数，可含零库存。
- production：最多32台机器的进度、电力、时钟、保存状态及站点库存。暂停时生产时钟不推进正常。
- client_waiting_for_host_mod 等待主机能力；client_joining 尚在加入；client_backpressure 表示需求满足、退避或积压；budget_yield 表示预算让出；waiting_for_receiver_refresh 等输入口刷新；error_disabled 表示异常后停用本会话物流。deliveryState 单独报告交付状态。

回执压缩保存在原版快照的 qt.receipt.v1: 与 qt.handoff.v1: 前缀零资源记录中，只保存编号范围，不增加可用资源。不要手动删除这些记录；读档后也据此避让已用编号。

日志收集只复制状态、限量日志、加载器日志/配置和文件哈希，不含存档、不上传。双人问题需双方日志。
